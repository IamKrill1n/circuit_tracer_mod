ADR 0003: FastAPI Visualization App

Status: Accepted

Summary. Build the graph visualization application as a small FastAPI server with vanilla JavaScript, while continuing to embed the stock circuit_tracer dashboard for graph rendering.

Context

The existing Streamlit app proves the local attribution, pruning, clustering, labeling, and dashboard-iframe workflow. The requested product shape is a graph-library dashboard with upload, generation, background jobs, and modal settings screens. That shape needs explicit API endpoints and polling, but it does not require a full frontend build system.

Decision

Add a separate FastAPI application under visualization_app/. The server owns graph library discovery, upload conversion, local attribution jobs, summary jobs, and circuit_tracer local-server lifecycle. The frontend is plain HTML, CSS, and JavaScript served by FastAPI.

Consequences

This keeps model and summarization work in Python, avoids importing Streamlit runtime state, and avoids introducing Node package management. The tradeoff is that the frontend uses lightweight hand-written JavaScript rather than React components, which is acceptable for the current modal and polling workflow.

Next Steps

If the UI grows into multi-page editing or complex stateful interaction, revisit a component frontend. Until then, keep circuit_tracer as the rendering authority and the FastAPI app as the graph-library control plane.
