Are our supernode interventions the same as the paper?

Compares summarization/summarize.py · circuit_tracer/replacement_model/replacement_model_transformerlens.py · eval/eval_intervention.py · app.py against the constrained / multiplicative patching of the Attribution-Graphs methods paper (Fig. 9, "Validation via interventions").

Verdict: Mostly faithful, with one concrete off-by-one in the patching window.

  • ✔ Multiplicative steering by M — we set each feature's new value to M · a_orig (per feature, at its active position). M = −1 gives the paper's negation. Exact match.
  • ✔ All features in the supernode are steered, and attention + LayerNorm are frozen (freeze_attention=True) so only the intervention changes MLP outputs. Match.
  • ⚠ Window semantics differ by one layer. Our default [l−1, l] (with l = the feature's own layer) injects the decoder write at the feature's own layer only. The paper's [ℓ−1, ℓ] (with the feature at ℓ−1) injects the own-layer write plus the first cross-layer write. We drop one decoder contribution the paper keeps.

1. What the paper does (Fig. 9)

"Pick a layer ℓ to intervene on. … Up to layer ℓ, we replace the output of each MLP with the recorded value plus a multiple of the steered feature decoders. After layer ℓ, we run the base model as usual." The figure steers a feature whose encoder lives at layer ℓ−1; the note "we don't use the crosscoder values after this layer" sits at ℓ+1. So:

  • Perturbed feature is at layer ℓ−1.
  • A CLT feature at layer L decodes into layers L, L+1, …, Lmax.
  • The patch window [ℓ−1, ℓ] applies the decoder write at ℓ−1 (own) and ℓ (first cross-layer); writes at ℓ+1… are dropped.
  • The second fetch quotes the paper verbatim: "we multiply a target feature's activation by M in the [ℓ−1, ℓ] layer range"; negation = "steer multiplicatively with a factor of −1".

So, normalized to a feature sitting at layer L (set ℓ−1 = L), the paper's effective write set is { L, L+1 }.

2. What our code does

2a. The value (the "× M") — matches

steer_interventions_constrained / _steer_interventions build value = factor · orig_activations[layer, pos, feat] per CLT feature at its active position. Inside feature_intervention, with a constrained window the delta is computed against the original activations:

delta   = value − a_orig = (factor − 1) · a_orig
written = decoder · delta      # so the feature's contribution becomes factor · a_orig · decoder

This is exactly multiplicative patching; factor = −1 reproduces the paper's negation. ✔

2b. The window — off by one layer

def constrained_window(layer, n_layers, layers_below, layers_above):
    return range(max(0, layer - layers_below), min(layer + layers_above + 1, n_layers))
# default below=1, above=0  ->  [layer-1, layer]   (layer = the FEATURE's own layer)

In feature_intervention, the decoder of a feature at layer L is scattered into layer_deltas[L … L_max] (CLT decodes only to layers ≥ L), but intervention_hook only adds layer_deltas[k] for k ∈ intervention_range = constrained_layers. With the default window {L−1, L}:

The L−1 slot is provably empty (a CLT never decodes below its own layer), so our default effective write set is { L } — the source feature's same-layer direct effect only. The code's own comment acknowledges this: "the l−1 slot carries no write — the effective direct effect is the source layer's own decode."

Root cause: the window is anchored to the wrong end. The paper's window's lower bound is the feature's layer (and extends one layer up); ours sets the feature's layer as the upper bound (and extends one layer down, into an empty slot). The docstring claim "Default (below=1, above=0) gives the paper's [l−1, l] range" reproduces the string but not the paper's set of patched layers.

4. Caveats on the two call sites

  • App steering UI / steer_interventions_constrained: per-source-layer windows; with the default this is the strict same-layer direct effect described above.
  • eval_intervention.steer_source_effects (Exp B): one window spanning [layer_min−1, layer_max] for the whole supernode. For a multi-layer supernode this does include cross-layer writes that land inside [feature_layer, layer_max], but features sitting at layer_max still get own-layer-only, and writes above layer_max are always dropped.
  • Exp A (setup_intervention single-feature) and Exp D (per-node ablation) are run unconstrained on purpose (full propagation) — those are not meant to match Fig. 9.

5. Does the discrepancy matter?

Both variants are valid "constrained / direct-effect" probes. Ours is strictly more constrained: it measures the pure same-layer decode and discards every cross-layer decoder output. The paper keeps the feature's full decode within the chosen window (in the figure: one extra layer). For a CLT the own-layer decode is usually dominant, but cross-layer writes are not negligible, so the intervention magnitude is systematically smaller than the paper's for the same M.
