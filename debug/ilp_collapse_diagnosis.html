MILP Mega-Cluster Collapse — Root-Cause Diagnosis

Stage-2 ILP clusterer (summarization/ilp_cluster.py) · diagnosed 2026-06-05 · all claims reproduced on synthetic instances

Summary. When max_layer_span is loose, cluster_graph_ilp() collapses feature nodes into a few huge supernodes, and raising lambda_causal to 100 barely helps. This is a formulation limitation, not a constraint bug — the transitivity / representative / budget constraints are all correct. The atomicity objective at the default theta=0 rewards every positive-cosine merge and contains no term penalising cluster size, so the global optimum is "merge everything the span allows." max_layer_span was the only thing preventing collapse. lambda_causal cannot substitute for it. The granularity lever you actually want is theta, not lambda_causal.

The objective

From ilp_cluster.py:130–141 and scoring.py:43–46, the ILP minimises a single binary program, linear in the same-cluster indicators xij:

minf ∑i<j xij (θ−cos(ri,rj)) + λ · |Wij|Wtotal

The two coefficient pieces per pair:

  • Atomicity: θ − cosij. At θ=0: a pair with cos > 0 gets a negative coefficient → merging is rewarded; only cos < 0 resists merging. Nothing penalises how big a cluster gets.
  • Causal: λ · |Wij| / Wtotal — a non-negative cost for merging a directly connected pair.

Root cause (two compounding facts)

  1. The atomicity term rewards collapse. Real feature role/phi vectors share structure, so most pairwise cosines are positive. At θ=0 each such pair is a merge reward and there is no size/count penalty, so subject only to transitivity and max_layer_span, the minimiser is one giant cluster. With a tight span the geometry forbade far-layer merges (ilp_cluster.py:99–104 + transitivity :167–181) — that was the real brake. Loosen the span and the brake is gone.
  2. lambda_causal structurally cannot fix it. Its coefficient is λ·|Wij|/Wtotal, which is identically 0 for any pair with no direct edge — and in a sparse pruned graph most feature pairs are not directly connected, so positively-correlated unconnected features merge for free at any λ. Even for connected pairs the penalty is divided by Wtotal (total pruned mass), making it tiny next to a cos ≈ 0.3–0.5 reward — so λ=100 is often still too small.

Verdict. Not a code bug — the constraints are correct. It is an objective-design limitation: cluster granularity is governed almost entirely by theta (the resolution threshold), with lambda_causal a weak secondary that is exactly zero on the many edge-free pairs. You have been sweeping the wrong knob.

Fix options (a design choice — nothing wired yet)

  1. Turn theta, not lambda_causal (no code change). Set theta from the cosine distribution of the role vectors (e.g. a high percentile of the positive off-diagonal cosines) and sweep theta for granularity. This is the intended lever — the docstring calls θ "the merge boundary."
  2. Hard cannot-link for cos < τ (≡ a hard θ): structurally set xij = 0 for low-similarity pairs. Guarantees no weak merges; adds constraints and one hyperparameter.
  3. Add an explicit size/count regulariser to the objective (penalise large clusters or reward more supernodes) if you want size control independent of the cosine scale.
  4. Insufficient alone: rescaling the causal term so λ has leverage — still null on edge-free pairs, so it can't prevent the dominant unconnected-feature collapse.

Note: max_sn will not help — it is an upper bound on the number of supernodes, so it can only make clusters fewer/bigger, never force more.
