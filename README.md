# Circuit Tracer Visualization Release 1.0

Minimal runtime release for the circuit tracing visualization stack. This branch keeps only
the code needed to install and run:

- `circuit_tracer`: attribution, replacement model, transcoder, and stock graph viewer assets
- `summarization`: pruning, clustering, labeling, summary graph serialization, and helper assets
- `visualization_app`: FastAPI dashboard, static UI, graph upload/generation, summary, and steering
- root helper modules: `config.py`, `api.py`, and `attribute_utils.py`

Generated datasets, notebooks, thesis files, evaluation scripts, archives, cached downloads, and
experiment outputs are intentionally not included.

## Requirements

- Python 3.10+
- NVIDIA GPU with CUDA for graph generation, SHAP token attribution, and steering
- A conda environment named `circuit`, or another environment with equivalent dependencies

## Installation

```bash
git clone <repo-url> circuit_tracer_release
cd circuit_tracer_release

conda create -n circuit python=3.10 -y
conda activate circuit

pip install -e ".[dev]"
```

If the environment already exists, keep using explicit `conda run -n circuit ...` commands when
running from automation.

## Configuration

Create a `.env` file at the repo root when you need external services:

```bash
NEURONPEDIA_API_KEY=
HUGGINGFACE_API_KEY=
GEMINI_API_KEY=
GENAI_API_KEY=
OPENAI_API_KEY=
```

`HUGGINGFACE_API_KEY` is also exported as `HF_TOKEN` when present. Labeling and Neuronpedia
lookups are optional; local attribution, pruning, and clustering do not require API keys.

## Start The Visualization App

```bash
conda run -n circuit python -m uvicorn visualization_app.server:app --host 0.0.0.0 --port 8000
```

Open `http://localhost:8000`.

The release starts with no bundled graph data. The app can still:

- upload a `.pt` attribution graph
- generate a new graph from a prompt
- convert graphs to the embedded viewer format
- run pruning, clustering, labeling, and summary graph generation
- run steering interventions on stored supernodes

Runtime data directories are created or read relative to the repo root as needed:

| Path | Purpose |
|---|---|
| `generated_graphs/` | Raw `.pt` graphs uploaded or generated by the app |
| `graph_files/` | Viewer JSON graph files |
| `summary/` | App-owned summary artifacts and supernode storage |
| `summary_graphs/` | Source-set summary graph artifacts |
| `downloads/hf_features/` | Optional local feature-dashboard mirror |

These directories are runtime state and are not committed on this release branch.

## Summarization CLI

```bash
conda run -n circuit python -m summarization --help
```

Example from an existing `.pt` graph:

```bash
conda run -n circuit python -m summarization \
  --graph-pt generated_graphs/capital_texas.pt \
  --no-auto-token-weights \
  --summary-graph-out summary/capital_texas.sng.pt
```

Example that attributes a prompt before summarizing:

```bash
conda run -n circuit python -m summarization \
  --prompt "The capital of Texas is" \
  --model google/gemma-2-2b \
  --transcoder mntss/clt-gemma-2-2b-2.5M \
  --graph-pt-out generated_graphs/capital_texas.pt \
  --summary-graph-out summary/capital_texas.sng.pt
```

## Circuit Tracer CLI

```bash
conda run -n circuit circuit-tracer --help
```

Example attribution command:

```bash
conda run -n circuit circuit-tracer attribute \
  -p "The capital of Texas is" \
  -t mntss/clt-gemma-2-2b-2.5M \
  -o generated_graphs/capital_texas.pt \
  --slug capital-texas \
  --graph_file_dir graph_files/custom/capital-texas
```

