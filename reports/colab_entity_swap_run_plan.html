Run eval/eval_entity_swap.py on Colab from VS Code

Created for /home/tu/circuit_tracer_mod.

Summary

Use the VS Code Colab extension as a notebook-backed remote runtime, then run shell commands from notebook cells. Colab does not automatically see files from /home/tu/circuit_tracer_mod; the runtime needs its own copy of the repo and the experiment inputs.

For this eval, the smallest practical data payload is the prepared labeled summary graph directory, not the raw dataset. The script requires exactly 000.sng.pt through 099.sng.pt plus bats_analogies.txt. Locally, those can be derived from labeled_summary/entmax/alpha_0.50/node_0.02/*_labeled_summary_graph.pt, which is about 1.9 MB, while dataset/analogies is about 11 GB. Those compact summaries are tracked in git, so the included notebook can prepare the expected graph directory after cloning the repo.

Assumptions

  • You want to use the official Google Colab VS Code extension with a Colab GPU runtime.
  • You can either push this repo to GitHub or otherwise upload/sync it into Colab.
  • You want to run the existing prepared entmax labeled summaries unless you intentionally regenerate summaries in Colab.
  • On Colab, use the runtime Python environment directly; the local conda run -n circuit convention does not apply unless you install conda inside Colab.

Does Colab Have Access To The Dataset?

No, not by default. A Colab kernel is a remote runtime. Opening a local notebook in VS Code and selecting a Colab kernel does not make /home/tu/circuit_tracer_mod/dataset readable from the Colab VM.

Give Colab access by one of these routes: clone/pull a repo or branch, upload a zip/tarball, mount Google Drive, download from cloud storage, or use a local runtime instead of a Colab hosted runtime. For this specific eval, cloning the repo is enough if the tracked compact summaries are present. Upload/sync the compact prepared summaries rather than the 11 GB raw analogies graph directory unless you need to regenerate them.

Prepared Notebook

A ready-to-run notebook has been added at colab_entity_swap.ipynb. Open that notebook in VS Code, select a Colab GPU kernel, and run top to bottom. It clones https://github.com/IamKrill1n/circuit_tracer_mod.git, checks out c0c035a, installs the package, creates generated_graphs/*.sng.pt from the tracked labeled summaries, smoke-tests relation 0, then launches the full eval.

If GitHub clone is blocked by private-repo authentication, upload /tmp/circuit_tracer_mod_colab_source.tgz to Colab and run the fallback source setup cell in the notebook.

Fallback Archives

Two local archives have been prepared: /tmp/circuit_tracer_mod_colab_source.tgz contains the tracked source plus compact summaries, excluding raw/generated graph directories. /tmp/entity_swap_inputs.tgz contains only bats_analogies.txt and prepared generated_graphs/*.sng.pt.

Run this locally from /home/tu/circuit_tracer_mod to create the exact graph directory that eval_entity_swap.py expects:

mkdir -p /tmp/entity_swap_inputs/generated_graphs
cp bats_analogies.txt /tmp/entity_swap_inputs/
for src in labeled_summary/entmax/alpha_0.50/node_0.02/*_labeled_summary_graph.pt; do
  stem=$(basename "$src" _labeled_summary_graph.pt)
  cp "$src" "/tmp/entity_swap_inputs/generated_graphs/${stem}.sng.pt"
done
tar -C /tmp -czf /tmp/entity_swap_inputs.tgz entity_swap_inputs
ls -lh /tmp/entity_swap_inputs.tgz

Upload /tmp/entity_swap_inputs.tgz to Colab only if you cannot clone the tracked compact summaries from git. If the extension has a file upload command, use that. Otherwise put it in Google Drive or upload it through a Colab notebook cell.

VS Code Colab Setup

  1. Install the official Google Colab extension in VS Code. It uses the Jupyter notebook flow.
  2. Open or create a notebook in this workspace, for example colab_entity_swap.ipynb.
  3. Click Select Kernel → Colab → connect to a GPU runtime.
  4. Run the cells below inside the notebook. They execute on the Colab VM, not on your local machine.

Run a small smoke test first, one relation only:

!mkdir -p runs eval_outputs/entity_swap_colab_smoke
!python -u eval/eval_entity_swap.py \
  --graph-dir generated_graphs \
  --analogies-file bats_analogies.txt \
  --relations 0 \
  --negation-coefficients -2 \
  --addition-coefficients 2 \
  --output-dir eval_outputs/entity_swap_colab_smoke \
  --device cuda \
  --dtype bfloat16 \
  2>&1 | tee runs/entity_swap_smoke.log

If the smoke test completes and writes CSVs, run the full sweep:

!mkdir -p runs eval_outputs/entity_swap_colab
!nohup python -u eval/eval_entity_swap.py \
  --graph-dir generated_graphs \
  --analogies-file bats_analogies.txt \
  --output-dir eval_outputs/entity_swap_colab \
  --device cuda \
  --dtype bfloat16 \
  > runs/entity_swap_full.log 2>&1 & echo $! > runs/entity_swap_full.pid

Monitor progress:

!tail -n 80 runs/entity_swap_full.log
!ls -lh eval_outputs/entity_swap_colab

Common Failure Points

  • expected 100 numeric .sng.pt files: you uploaded raw .pt files or wrong names. The eval wants 000.sng.pt ... 099.sng.pt.
  • CUDA out of memory: use a larger Colab GPU, reduce coefficients/relations for a partial run, or try --dtype float16.
  • Model download denied: accept model terms or log in to Hugging Face with a token that can access google/gemma-2-2b.
  • Output disappears after disconnect: copy eval_outputs/entity_swap_colab off the Colab VM before the runtime is recycled.
