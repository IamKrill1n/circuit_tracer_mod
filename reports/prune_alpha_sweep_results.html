Summary

α controls the influence↔relevance mix in the combined prune score (α·influence + (1−α)·relevance, geometric/rank). The sweep reveals a clean tradeoff with no universal winner:

  • Completeness & replacement (backward, influence-derived) improve with higher α at every fixed node count — α=1 dominates, α=0 is worst.
  • Token-attribution-faithfulness (forward, relevance-derived) does the opposite — lower α dominates.
  • Each metric rewards its own side of the score; α≈0.5 is the balanced compromise. All α converge at threshold=1.0 (the full graph).

softmax and entmax token-normalizations give near-identical curve shapes (entmax slightly lower completeness at thr=1.0 because it zeroes more tokens).

Interpretation

The two backward metrics (completeness, replacement) are computed from influence flowing back from the target logit, so they mechanically favour the influence term (high α). Token-attribution-faithfulness measures how much of each input token's forward relevance to the target survives pruning, so it favours the relevance term (low α). This is the expected signature of a genuine influence/relevance blend — neither end is strictly better, which is the argument for keeping both terms rather than pruning on influence alone.

Caveat (circularity): token-attribution-faithfulness is weighted by the same SHAP token weights used to build the relevance seed, so the low-α advantage on taf is partly self-fulfilling. Treat the completeness/replacement curves as the more independent evidence, and taf as a diagnostic of how much token-relevance the prune retains.

Run notes (infrastructure)

  • SHAP alignment: all 100 graphs initially failed an off-by-one (raw_shap included the scaffold ':' while the graph mask flagged it special). Resolved by reverting summarization/token_attribution.py to bfa1a50, which matches how shap_values.json was generated (only <bos> special).
  • Disk: the original two-stage path (prune_graphs.py → eval_prune.py) saves ~140 MB per PruneGraph; a 9,000-cell sweep needs ~0.5 TB and crashed the disk at 100%. Replaced with the fused in-memory script eval/prune_eval_fused.py (prune → metric → row; ~5 MB total output).
  • Compute: ran on cuda:0, per-graph GraphCache to bound GPU memory; ~55 min wall.
