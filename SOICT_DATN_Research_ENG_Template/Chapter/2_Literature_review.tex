\section{Mechanistic Interpretability and Circuits}
\label{sec:mech-interp}
% The purpose of this section is to introduce the key concepts of mechanistic interpretability and circuits, and to explain how they relate to the methods developed in this thesis. The section is organised into three parts: the first part defines mechanistic interpretability and its goals; the second part introduces the concepts of features, circuits, and superposition; and the third part explains how these concepts motivate the use of sparse autoencoders and transcoders for circuit analysis.
Mechanistic interpretability is a subfield of explainable AI (xAI) that aims to reverse-engineer the internal workings of a model, from its weights down to human-interpretable mechanisms. Unlike behavioural interpretability, which studies the relationship between inputs and outputs while treating the network as a black box, mechanistic interpretability seeks to recover the exact algorithm the model implements internally; the analogy often used is decompiling a compiled binary back into readable source code. Three concepts organise this programme and recur throughout the thesis: features, circuits, and superposition.

A \emph{feature} is the basic unit of representation: a property of the input that the model computes and reuses across contexts, such as the presence of a particular concept or syntactic role. The \emph{linear representation hypothesis} states that a feature corresponds to a direction in activation space, with the strength of the feature given by the magnitude of the activation along that direction~\cite{elhage2021framework}. This hypothesis is natural for transformers because their computation is dominated by linear maps acting on the residual stream, so semantically meaningful properties can be encoded as directions and recovered by projection. Features are the nodes from which interpretable mechanisms are built.

A \emph{circuit} is a subgraph of the model's computation that maps a set of earlier features to a set of later features, comprising the specific weights and non-linearities used in that mapping~\cite{olah2020zoom}. Features compose hierarchically: early layers compute simple features that later layers combine into increasingly abstract ones, and the residual stream lets a circuit span non-adjacent layers by carrying intermediate features forward unchanged. Identifying circuits is the central goal of this thesis, since a circuit expressed over interpretable features explains not merely \emph{what} a model predicts but \emph{how} the prediction is computed.

The obstacle to reading circuits directly off neurons is \emph{superposition}: a model represents more features than it has dimensions, packing them as an overcomplete set of nearly orthogonal directions in activation space~\cite{elhage2022superposition}. A direct consequence is \emph{polysemanticity}, where a single neuron activates for several unrelated features and therefore admits no single interpretation. Superposition is an efficient compression strategy for the model but a fundamental barrier for interpretation, because the natural computational basis (neurons) no longer aligns with the natural representational basis (features). Overcoming this misalignment is precisely what the dictionary-learning methods of the next section are designed to do.
\section{Sparse Autoencoders and Transcoders}
\label{sec:sae-transcoder}
% The purpose of this section is to introduce the concepts of sparse autoencoders and transcoders, and to explain how they can be used to recover interpretable features and circuits from a model. The section is organised into two parts: the first part defines sparse autoencoders and their training objective; the second part introduces transcoders as a variant of sparse autoencoders that can be used to recover feature-to-feature interactions, and explains how they enable the circuit-tracing pipeline of the next section.
Sparse autoencoders (SAEs) address the polysemanticity barrier by learning a representational basis that is aligned with features rather than neurons~\cite{cunningham2023sparse}. Framed as dictionary learning, an SAE encodes a model activation $x \in \mathbb{R}^{d}$ into a sparse, overcomplete code $c = \mathrm{ReLU}(W_{\mathrm{enc}} x + b)$ with far more entries than $d$, and reconstructs the activation from that code as $\hat{x} = W_{\mathrm{dec}} c$. Training minimises a reconstruction term and an $\ell_1$ sparsity penalty,
\begin{equation}
\mathcal{L}(x) = \lVert x - \hat{x} \rVert_2^2 + \alpha \lVert c \rVert_1 ,
\end{equation}
where $\alpha$ trades reconstruction fidelity against sparsity. Because only a few code units are active at a time, each unit can specialise to a single feature, and the resulting dictionary directions are substantially more monosemantic and interpretable than individual neurons. SAEs thus recover, in an unsupervised way, the feature directions that superposition had hidden.

SAEs nevertheless remain awkward for circuit analysis, because they are trained to reconstruct one activation in place and say nothing directly about how features at one site cause features at another. A \emph{transcoder} is a variant designed to close this gap~\cite{dunefsky2024transcoders}: instead of reconstructing its input, it predicts the \emph{output} of an MLP sublayer from that sublayer's \emph{input}. With the same sparse encoder $z(x) = \mathrm{ReLU}(W_{\mathrm{enc}} x + b_{\mathrm{enc}})$ and a decoder $\mathrm{TC}(x) = W_{\mathrm{dec}} z(x) + b_{\mathrm{dec}}$, a transcoder is trained to approximate the MLP map,
\begin{equation}
\mathcal{L}_{\mathrm{TC}}(x) = \lVert \mathrm{MLP}(x) - \mathrm{TC}(x) \rVert_2^2 + \lambda \lVert z(x) \rVert_1 .
\end{equation}
By replacing the MLP with a sparse linear map over interpretable features, the transcoder \emph{skips over} the MLP non-linearity that otherwise blocks attribution. The effect of one feature on another then factorises into an input-dependent term, the source activation, and an input-invariant term given by the dot product between the source decoder direction and the target encoder direction, which depends only on the learned weights. This factorisation is what makes feature-to-feature edges cheap and faithful to compute, and it is the property the circuit-tracing pipeline of the next section is built upon.

\section{Automated Interpretation Methods}
\label{sec:autointerp}
Recovering a feature direction is only half of interpretation; the direction must still be assigned a human-readable meaning, and doing this by hand does not scale to the millions of features a dictionary can contain. Automated interpretation (auto-interp) addresses this by using a large language model to generate natural-language descriptions of what a unit responds to~\cite{bills2023language}. The method was introduced for individual neurons but applies unchanged to the more interpretable features of SAEs and transcoders, and it underlies the public feature labels this thesis consumes through Neuronpedia.

The pipeline pairs two language models in an explain-then-verify loop. An \emph{explainer} model is shown a unit's top-activating text examples, annotated with per-token activation values, and is asked to write a short explanation of the pattern that drives the unit. A \emph{simulator} model is then given only that explanation, with no access to the true activations, and asked to predict the unit's activation on held-out text. The explanation is scored by the correlation between the simulated and the true activations, so that an explanation which genuinely captures the unit's behaviour earns a high score while a vague or incorrect one does not.

The principal limitation reported for raw neurons is a direct consequence of superposition: because neurons are polysemantic, a single sentence cannot describe their many unrelated activations, and the correlation scores are correspondingly low. This limitation is also the motivation for applying auto-interp to SAE and transcoder features instead, whose monosemanticity yields explanations that score far higher and can be trusted as node labels. Auto-interp therefore supplies the per-feature semantics that turn an attribution graph from an anonymous wiring diagram into a human-readable account of the model's computation.
